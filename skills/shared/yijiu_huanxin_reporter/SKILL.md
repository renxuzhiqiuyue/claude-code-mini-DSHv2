# 以旧换新月报 Skill

## 概述

本 Skill 定义 **怎么分析、怎么写**：先 **框架**（大纲 + 数据需求表），再 **按框架调工具填数**。推荐作为以旧换新任务 **第一个加载** 的 Skill。框架阶段禁止出现具体业务数字；填数阶段数字必须可追溯到 query JSON、根因 markdown 或 web JSON。

## 工作区与路径约定

- cwd = `OUTPUT_DIR`（默认 `.output/`，工具沙箱根）
- 所有路径**相对 OUTPUT_DIR**：`outline.md`、`data/`、`images/`
- **禁止** 逃逸 OUTPUT_DIR；**禁止** 无必要的 `bash mkdir`（`write_file` 会自动建父目录）（`write_file` 自动建父目录）

```
outline.md
report.md
data/          ← query_xx.json、web_xx.json、root_01.json
images/        ← chart_*.png、chart_root.png
```

- 出图：OUTPUT_DIR 下 `python ../skills/solver/local_chart/scripts/generate_charts.py --run-dir .`
- **禁止** 写入 OUTPUT_DIR 以外路径

## 核心能力

- 生成报告大纲、query_xx / web_xx / root_xx 需求表
- 规定全国 / 分公司 scope、章节结构与写作深度（WHAT → SO WHAT → NOW WHAT）
- 协调 SQL 取数、联网背景、根因两层下钻、业务图表与决策树出图
- 提供图表选型、占位符、正文模板与 Agent 自检 checklist

## 何时使用

**必须加载本 Skill 当：**

- 用户请求以旧换新月报、活动分析报告
- 需要确定报告结构、数据需求或写作规范
- 任何 SQL / 联网 / 根因 / 出图操作 **之前**（须先出框架）

**不要跳过框架：** 禁止未出框架就执行 SQL 或编造指标。

## 工作流程

### 阶段 1：框架（无数字）

1. 解析报告范围（月份、品类、scope、是否含根因/联网）
2. `write_file` `outline.md` + 数据需求表（query / web / root）
3. 框架中含 `【图：…】` 占位符

### 阶段 2：取数与增强

4. `load_skill(read-sql-data)` → 按 query_xx：checker → query → write_file
5. `tavily_search` 按 web_xx（≤3 次）
6. `load_skill(root-cause-tracer)` + `read-root-cause` → fetch → build → root_01.json → 决策树出图

### 阶段 3：成稿

7. `read_file` `outline.md` + 全部 `data/*.json` → 按深度规范 `write_file report.md`
8. `load_skill(local-chart)` → 业务图表 PNG
9. 格式与深度自检

| 类型 | 工具 / Skill | 可用于 | 禁止 |
|------|--------------|--------|------|
| **业务指标数字** | `read-sql-data` → `sql_db_query` | 表格、金额、笔数、占比 | 凭经验或联网数字填表 |

### query_xx 固定编号（与 local-chart 对齐，禁止颠倒）

| 编号 | 报告小节 | JSON 关键字段 | 出图 |
|------|----------|---------------|------|
| query_04 | 3.2 性别分布 | `rows[].sex` | 无 |
| query_05 | 3.1 年龄分布 | `rows[].age_group` | **chart_2 柱形图** |
| query_06 | 3.3 城市分布 | `rows[].rec_city_nm` 或城市字段 | 无 |

**常见错误（会导致 chart_2 无法出年龄图）：**

- 年龄 SQL 写入 `query_04.json`、性别 SQL 写入 `query_05.json` — **编号与 local-chart 冲突**
- `query_05.json` 的 `rows` 只有 `sex` 没有 `age_group` — chart_2 标签全为「未知」

框架 `数据需求表` 须按上表编号；填数时 **年龄段落读 query_05、性别段落读 query_04**。

## 联网检索（tavily_search）

用于 **叙述性背景** 与 **公开可查的数据**，补充报告深度。  
**分公司库内业务指标**（交易笔数/金额/补贴等）仍 **必须** 来自 SQL；联网可补充：

- 国家/地方以旧换新 **政策** 与活动动态
- 行业新闻、消费趋势 **叙述**
- 政府、统计局、媒体 **公开发布** 的行业/全国/省级统计（作对照、背景，须注明来源与口径）
- 与报告月相关的 **公开数据**（如全国以旧换新累计规模、品类公开统计等）

**不可**：用联网搜到的公开数 **冒充** 本库 SQL 明细表格数据。

### 何时调用

- 框架 `数据需求表` 中列了 `web_xx` 才调用
- 每份报告 **≤3 次** `tavily_search`
- 在 SQL 取数之后、写正文之前执行

## 分析角度与写法

**禁止「只报数、不解释」**：表格/图表前后必须有分析叙述，说明 **现象 → 含义 → 启示**，不能只罗列 query 结果。

**排版原则（穿插式，强制）**：表格与图片 **嵌入分析叙述中间**，采用「**叙述 → 表格/图 → 叙述 → … → 结论**」交替结构；**禁止**把表格、图片全部堆在章节或小节末尾。

| 禁止 | 推荐 |
|------|------|
| 先写满全文，最后附一张总表 + 一张总图 | 结论句 → 表格 → 解读表内关键行 → 图表 → 图后印证 → 结论建议 |
| 表格/图之间无文字、形成「数据附录」 | 每个表格/图 **上下各至少 1 段** 分析，形成夹心结构 |

### 一、活动概况

- 先「谁、何时、什么活动、口径」+ **政策背景（web）**，再给 **SQL 总量指标**
- 数字只来自 query_01，背景只来自 web_01
- **至少 2 段叙述**：① 结论先行概括全年/当月体量；② 结合 web 政策与公开数据作 **狭义/广义对照**（注明口径差异）

### 二、交易规模与结构（重点章节，篇幅要足）

每节按 **WHAT → SO WHAT → NOW WHAT** 展开，推荐 **穿插式** 结构（数字为最低要求，表/图须夹在叙述中）：

1. **结论段（WHAT）**：点明当月/累计规模与环比方向（含具体数字与环比率）
2. **表格**（query 明细）：紧接结论段，用表格呈现品类/规模数据
3. **结构段（SO WHAT）**：**紧接表格**，解读表内关键行——谁主导、是否集中、长尾表现
4. **【图：各品类交易金额占比】**：放在结构段之后；**图前 1 句**引入（如「下图进一步呈现金额权重」），**图后 1～2 句**印证表格
5. **动因/趋势段** + **【图：各品类交易金额环比对比】**（若有 query_03）：折线图同样 **夹在动因叙述中间**，而非章节末尾
6. **分析结论与建议**：80～150 字，收束全节

### 三、用户画像

- 性别、年龄、城市各小节：**结论句 → 表格 → 表后解读 →（年龄节）【图：用户年龄分布】夹在解读中 → 结论建议**
- 年龄：表格列出分布后 **再** 插柱形图，图后继续写峰值区间、政策人群吻合度
- 城市：表后写 TOP 城市集中度，**不要**等整章写完再统一贴表

### 四、商户与渠道

- 除 TOP 表格外，写 **集中度**（头部商户贡献占比）、 **客单/笔均**（若 query 有）、渠道结构启示

### 五、变化原因

- 仅根因工具 markdown + 决策树图；无 root 数据则 **整章删除**
- 叙述须含：整体异动 → **第 1 层** 全维度解释力得分 + Top5/其他 → **第 2 层**（排除「其他」后全局下钻）→ 业务含义
- **【图：根因下钻决策树】**：`generate_drill_tree.py` 生成，夹在两层解读之间
- **禁止** 只写第一层、超过两层、或省略各维度解释力得分表

### 六、总结与建议

- 3～5 条建议，每条 **呼应前文 SQL/根因发现**，避免空泛
- 宏观可引用 web_02，与库内结论 **对照** 而非混用口径
- **禁止建议**：调整优惠力度、优化券种/活动设计、拓展省外用户
- 文末固定：  
  `（注：本报告分析结论和建议由满血版本根据活动数据表现推理得出，供参考）`

## 正文深度写作规范（强制）

填数写 `report.md` 时 **必须** 遵守本节；仅改数字、不写分析视为 **未完成**。

### 1. 分析框架：WHAT → SO WHAT → NOW WHAT

| 层次 | 含义 | 写法 |
|------|------|------|
| **WHAT** | 数据说了什么 | 用 query 数字描述规模、占比、环比、分布 |
| **SO WHAT** | 对业务意味着什么 | 结构是否集中、谁拉动、是否异常、与政策/季节是否吻合 |
| **NOW WHAT** | 建议跟踪什么 | 写入「分析结论与建议」，可执行、可验证 |

### 2. 篇幅与结构（最低要求）

| 部分 | 最低要求 |
|------|----------|
| **摘要** | 100～150 字，含 1 个核心结论 + 1 个结构/环比发现 |
| **每个一级章节** | 除表/图外，**≥200 字** 分析叙述；表/图 **分散** 在叙述中，非集中堆在段末 |
| **每个二级小节** | **≥120 字** 现象解读；**结论句 → 表格 → 表后解读 →（可选）图 → 图后解读 → 结论建议 80～150 字** |
| **表格** | 表 **前** 须有引入句（说明表展示什么）；表 **后** 须有解读句（点明关键行/极值/占比），禁止裸表 |
| **图表** | 图 **前** 引入 + 图 **后** 印证，各 **≥1 句**；图须夹在相关叙述中间，禁止章节末尾集中贴图 |

### 3. 常用分析表述模板（按需选用，数字须来自 query）

**规模与总量**

- 「{月份}单月交易 **{笔数} 笔**、金额 **{金额} 万元**，累计口径下全年已达 **{累计} 万元**，体量{偏大/适中/偏小}。」
- 「从绝对量看，{品类/城市}为当前{最大/次要}贡献来源。」

**环比变化**（正用「环比上升」，负用「环比下降」，正文不写负号）

- 「较{上期} **{上期金额} 万元**，{本期} **{本期金额} 万元**，环比{上升/下降} **{比率}%**，{延续回暖/短期波动/增速放缓}。」
- 「环比变动中，**{品类/维度}** 贡献约 **{贡献占比}%** 的增量，是本月{增长/回落}的{主要/次要}驱动因素。」

**占比与结构**

- 「{A 品类}占比 **{占比}%**，{居首/次之}；与 {B 品类}（**{占比}%**）形成「双核」格局，合计覆盖 **{合计占比}%** 以上交易金额。」
- 「{长尾品类}占比不足 **{占比}%**，对整体规模影响有限，但可观察活动覆盖是否到位。」
- 「结构较上期{更加集中/趋于分散}：{领先品类}占比{提升/下降} **{百分点} 个百分点**（须 query_02/03 可算时才写）。」

**分布与集中度**

- 「{年龄段/城市}呈现{纺锤形/头部集中}分布：**{区间/城市}** 用户/金额贡献最高，是核心客群/区域。」
- 「城市维度上，**{TOP1 城市}** 集中 **{占比}%** 交易金额，省内/全国{区域均衡性较好/头部效应明显}。」

**图表解读**

- 「饼图显示 {品类} 金额权重过半/近四成，与表格占比一致，结构{稳定/调整}。」
- 「折线图对比当期与基期，{品类} {走高/回落/持平} 最为明显，与环比结论相互印证。」

**对照表述**（web 公开数据，须标注来源）

- 「据公开信息，{来源}显示全国/行业 {指标} 为 **{数字}**（口径：{说明}），与库内 {scope} SQL 汇总{同向/存在差异}，{差异原因/分开阅读}。」

### 4. 反例 vs 正例（第二章片段）

**反例（禁止）**——表/图堆在段末、无夹心叙述：

```
12月交易154笔，金额70.70万元，环比上升10.23%。
（大段文字全写完…）
| 品类 | ... |
【图：各品类交易金额占比】
【图：各品类交易金额环比对比】
分析结论：家电仍是第一大品类。
```

**正例（目标）**——**穿插式**：叙述 ↔ 表格 ↔ 叙述 ↔ 图 ↔ 叙述 ↔ 结论：

```
  2025年12月单月，以旧换新交易 **154 笔**、金额 **70.70 万元**，较11月 **64.14 万元** 环比上升 **10.23%**，延续温和回升态势。各品类明细如下：

| 品类 | 12月笔数 | 12月金额（万元） | 占比 |
|------|---------|----------------|------|
| 家电 | 79 | 43.83 | 62.00% |
| 手机数码3C | 74 | 26.37 | 37.30% |
| 家居家装 | 1 | 0.50 | 0.70% |

  表内可见，**家电** 占比 **62.00%** 居首，**手机数码3C** **37.30%** 次之，两者形成「双核」格局；**家居家装** 仅 **0.70%**，属长尾品类。

  下图进一步呈现各品类金额权重分布：

  【图：各品类交易金额占比】

  饼图与上表一致，家电过半、双品类主导结构清晰。

  环比维度上，（结合 query_03）**家电** 增量高于整体，是本月规模抬升的主要动力。当期与基期对比如下：

  【图：各品类交易金额环比对比】

  折线图显示 {具体品类} 变化最为明显，与上文环比结论相互印证。

  **分析结论与建议**：本月增长由家电品类主导，结构集中度较高；建议持续跟踪家电国补/地补执行与客单变化，并观察手机数码3C 是否能在旺季形成第二增长极；家居家装可结合活动覆盖范围评估后续放量空间。
```

### 正文核心规则

1. 业务数字 **必须来自 query_xx**；无法追溯 → **删除**该段

3. 数值：≥1万→「万」；≥1亿→「亿」；两位小数
4. 环比：正「环比上升」，负「环比下降」，正文不写负号

## 图片与占位符

### 图表选型（与 local-chart 一致，强制）

| 分析目的 | 类型 | 占位符示例 | chart |
|----------|------|------------|-------|
| 根因决策树 | **决策树** | `【图：根因下钻决策树】` | chart_root |
| 占比 / 构成 | **饼图** | `【图：各品类交易金额占比】` | chart_1 |
| 时间/两期趋势对比 | **折线图** | `【图：各品类交易金额环比对比】` | chart_3 |
| 各数据项横向对比 | **柱形图** | `【图：用户年龄分布】` | chart_2 |

- **占比** → 饼图；**趋势/环比/两期对比** → 折线图；**年龄段/城市/商户等项间对比** → 柱形图
- **禁止** 用柱形图展示占比、用饼图展示趋势、用折线图替代离散项横向对比

| 阶段 | 写法 |
|------|------|
| 框架/大纲 | `【图：…】` 占位符写在 **对应分析段落之间**（非章末）；大纲注明「表前/表后/图前/图后」各需解读句 |
| 终稿（local-chart） | 图表 **嵌入** 叙述流；`chart_1/2/3.png` 前后须有引入与印证句 |

图表数据 **必须** 来自 `data/query_xx.json`，由 **`local-chart` Skill** 在 OUTPUT_DIR 下调用本地 Python 生成，不能来自联网。

出图命令见 `load_skill(local-chart)`；在 OUTPUT_DIR（默认 `.output/`）下执行：

```bash
python ../skills/solver/local_chart/scripts/generate_charts.py --run-dir .
```
